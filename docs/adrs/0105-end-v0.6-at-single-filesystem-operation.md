# ADR 0105: End version 0.6 at single-filesystem operation

- Status: Accepted
- Date: 2026-09-13
- Supersedes: ADR 0087 (unreleased release numbering only)

## Context

ADR 0087 promoted a fine-grained operator-experience sequence from version
0.6.0 through version 0.6.17. Versions 0.6.0 through 0.6.8 are now released.
They establish one-invocation operation, checkpoint consent, human and machine
reports, private resume and unattended authority, logging and visibility
policy, and honest retained-in-place duplicate disposition.

The next planned release, same-filesystem managed quarantine, completes the
single-collection workflow while retaining the filesystem's atomic rename
boundary. The following planned release crosses a materially different safety
boundary: an atomic move is no longer available, so pymo must preflight
capacity, copy content, verify it, publish without replacement, and recover
honestly from interruption. Later queue and scheduler work extends that broader
operation across collections and storage topology.

Keeping every item under version 0.6 would preserve the original numbering but
would obscure the transition from a practical single-filesystem operator to
multi-filesystem and multi-collection orchestration. None of the affected
versions has been tagged or released, so the roadmap can adopt the clearer
boundary without changing a shipped interface or artifact.

## Decision

Version 0.6.9 remains same-filesystem managed quarantine and becomes the final
version 0.6 release.

The remaining approved work keeps its order and acceptance scope but is
renumbered:

| Former version | New version | Primary purpose |
| --- | --- | --- |
| 0.6.10 | 0.7.0 | Cross-filesystem managed quarantine |
| 0.6.11 | 0.7.1 | Queue manifest and planning |
| 0.6.12 | 0.7.2 | Sequential queue execution |
| 0.6.13 | 0.7.3 | Queue recovery |
| 0.6.14 | 0.7.4 | Queue synopsis |
| 0.6.15 | 0.7.5 | Storage-aware scheduler measurements |
| 0.6.16 | 0.7.6 | Bounded intra-collection scheduling |
| 0.6.17 | 0.7.7 | Bounded cross-collection scheduling |

Version 0.7 is the multi-filesystem and multi-collection orchestration line.
Its first release establishes the cross-filesystem safety foundation before a
queue can depend on it. Sequential operation remains the default until measured
evidence justifies each bounded scheduling layer.

Accepted ADR 0087 remains unchanged as the historical record of the original
promotion. This ADR supersedes only its numbering and version-theme allocation
for work that was still unreleased on 2026-09-13. It does not alter the scope or
truth of any released version.

## Consequences

- Version 0.6 has a coherent endpoint: safe single-collection operation and
  duplicate disposition on one filesystem.
- Version 0.7 begins where pymo must use a copy-and-verify protocol rather than
  an atomic move, then extends that foundation into queues and measured
  scheduling.
- Current roadmap, research, handoff, README, and project-instruction surfaces
  use the new numbering; immutable historical ADRs and release records retain
  the numbering that was true when written.
- Version 0.6.9 still requires its own claim, implementation ADR, tests,
  independent review, protected pull request, release tag, and acceptance
  evidence.
- This decision changes no runtime, package, command, report, cache, journal,
  migration, media, or release-tag behavior.
- Permanent duplicate deletion remains outside both version lines.
