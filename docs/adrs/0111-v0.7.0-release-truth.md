# ADR 0111: Record v0.7.0 release truth after publication

- Status: Accepted
- Date: 2026-11-07
- Applies: ADR 0090, ADR 0109, ADR 0110

## Context

Version 0.7.0 was tagged from the reviewed source tree while its documentation
still accurately described an unpublished candidate. Publication is now proven;
current documentation should record that fact without altering the tag.

Independent Terra-medium review accepted implementation `57e0fdf` after closing
COPY-R01 through COPY-R03, then accepted documentation head
`fe28e12934113b2a701b29a5e634a492237b506c`. The owner ran 697 tests at 87 percent
subprocess-aware coverage. Two distinct-filesystem fixtures skipped in the
ordinary macOS run passed separately on a disposable APFS volume. Static checks,
hooks, archive/license inspection, builds, isolated installed-copy acceptance,
and exact source-retaining recovery checks passed.

PR #69 run `42334776314` passed Ubuntu, Fedora, macOS and the unconditional
quality gate. Protected merge `2af3cb4c32f5ef575dcddce4f4699176c65a2b0a` passed
exact-main run `42335212722`. Following explicit maintainer approval, annotated
tag `v0.7.0` object `580f88f889ac31dc32032c0f0c03279672bde77f` was published
at that merge. Tag-triggered run `42335973647` passed build and isolated
installation verification. Remote tag and peeled target were read back exactly.

The locally built tagged wheel SHA-256 is
`d3cc848f9fe63d95fff3119f4ac82b7c68f418242b1f2875d1bb99cafda8798e`; the
source-distribution SHA-256 is
`cf733d6f02a5867bdfc15033b3e725bf3be7b8ef85db3483fc3ca808ca68e547`.
Every packaged module matches the accepted executable artifact. Isolated
version and strict coordinator-state/report smoke checks passed, and the
uv-managed command reports `pymo 0.7.0`.

## Decision

Use a separate documentation-only pull request to mark version 0.7.0 released,
reconcile current command/schema guidance, and record the evidence above.
The immutable tag remains fixed at the protected implementation merge. The
later main documentation is the authoritative current release-status view.
No package behavior changes and no PyPI publication are included.

## Consequences

- Copy mode retains original duplicates and interrupted artifacts; it does not
  delete, overwrite, or claim reclaimed capacity or complete filesystem metadata
  preservation. Same-filesystem move/undo remains distinct.
- Version 0.7.1 reviewed policy authoring is next; queue work continues through
  0.7.5. Production readiness remains a separate assessment under ADR 0109.
- Synthetic and disposable-filesystem acceptance met this release's boundaries;
  no private media collection, baseline, planner, or retained evidence changed.
