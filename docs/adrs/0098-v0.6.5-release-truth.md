# ADR 0098: Record v0.6.5 release truth after publication

- Status: Accepted
- Date: 2026-09-12
- Applies: ADR 0090

## Context

Version 0.6.5 was deliberately tagged from a source tree whose changelog and
roadmap still described it as an unreleased candidate. That statement was true
before publication and preserved the release boundary required by ADR 0090.

The release has now crossed its protected publication boundary. Current
documentation on `main` should record the completed facts without changing the
immutable release tag.

The final owner head is
`784f05c1f86075c33137900c771e1388949589d2`. PR #56 passed its full hosted
gate and merged through the protected merge-commit path as
`b4a4c48ab0ce80f3021f13b2bc65e237b9859dec`. The exact merge passed the
separate full `main` gate before annotated tag `v0.6.5` was created. The tag
peels to that merge, its release workflow passed, independent tagged artifacts
were built and installed, and the iMac's uv-managed command reports
`pymo 0.6.5`.

Post-tag acceptance exercised the tagged installed command on fresh clones of
two retained real working collections: one routine and one with reviewed
validation findings plus exact image and video duplicates. The unattended mode
crossed only matching pre-authorized checkpoints, retained the external
duplicate-review stop, and reached complete observed preservation plus recorded
human sign-off after that intact tree was moved and the same policy resumed.
Independent SHA-256 inventories matched both final working namespaces and the
applicable retained review tree to their separately reviewed policy-source
results. The private authority store also rejected group-writable mount
ancestry and succeeded beneath trusted owner-private ancestry. Collection
identities, paths, statistics, findings, and timings remain outside the public
repository.

## Decision

Use a separate documentation-only pull request after the v0.6.5 tag to record
the release evidence and promote the roadmap entry from release candidate to
released.

The reconciliation does not move or recreate v0.6.5, alter package behavior,
or begin v0.6.6 implementation. The tagged source remains an accurate snapshot
of the pre-publication candidate state; the later `main` documentation is the
authoritative current release-status view.

## Consequences

- V0.6.5 release claims remain limited to observed publication evidence.
- Real-collection acceptance corroborates exact policy advancement, deliberate
  quarantine pausing and resume, final reporting, and fail-closed private-state
  placement without expanding product authority.
- The immutable tag remains fixed at the reviewed product release merge.
- Version 0.6.6 requires its own claim, branch, worktree, ADR, implementation,
  review, and release boundary.
